# 什么是节点？

<AnswerBox question="在代理网络中，所谓的“节点”到底指什么？">
“节点 (Node)”是指一台部署在特定机房中的**远端代理服务器实例**。它具备独立的 IP 地址、端口号、加密协议与认证密钥。当客户端连接到该节点后，所有出站流量都由这台服务器代理向外发起。
</AnswerBox>

## 🧭 节点的命名与信息结构

在客户端的节点列表中，一个标准的节点名称通常包含以下关键要素：

```
[香港 01] [IEPL专线] [流媒体解锁] [1.5x]
  │           │            │          │
  │           │            │          └── 计费倍率
  │           │            └──────── 业务特性标签
  │           └────────────────────── 网络传输类型
  └────────────────────────────────── 物理落地地区
```

### 1. 物理落地地区 (Location)
- **香港 (HK)**：物理延迟极低（通常 15~40ms），适合日常网页浏览、外贸办公与 Google 搜索。
- **日本 (JP)**：网络基础设施优良，延迟适中（40~80ms），适合亚洲区游戏与视频。
- **新加坡 (SG)**：东南亚核心互联中心，访问东南亚服务与 AI 平台稳定。
- **美国 (US)**：物理延迟较高（140~220ms），但 IP 资源丰富，流媒体与原生服务版权覆盖广。

### 2. 传输线路类型
- **直连 (Direct)**：本地客户端直接跨公网连接境外节点，延迟受公网拥堵影响较大。
- **中转 (Relay / Transit)**：先连接到国内优质入口服务器，再通过中转机转发到境外落地机。
- **IEPL / IPLC 专线**：走内网跨境光纤专线，完全规避公网波动与丢包，晚高峰极度稳定。

### 3. 计费倍率 (Multiplier)
- **1.0x**：标准倍率。消耗 1GB 实际流量，扣除套餐 1GB 额度。
- **0.5x / 0.2x**：低倍率/公益节点。适合大文件下载、系统更新等消耗海量流量的场景。
- **2.0x / 3.0x**：高倍率节点。通常为高成本的专线或稀缺住宅 IP，消耗 1GB 扣除 2~3GB 额度。

## 🔍 节点的关键技术参数

每个节点在底层配置文件中都包含以下核心字段：

| 参数项 | 说明 | 示例 |
| :--- | :--- | :--- |
| **Server (地址)** | 节点的域名或 IP 地址 | `hk01.example.com` |
| **Port (端口)** | 代理服务端监听的端口 | `443` 或 `8443` |
| **UUID / Password** | 用于身份认证的唯一密钥 | `9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d` |
| **Protocol (协议)** | 客户端与服务端通信协议 | `VLESS`, `Trojan`, `Shadowsocks`, `Hysteria2` |
| **Transport / TLS** | 传输层与安全伪装设置 | `gRPC + TLS`, `WS + CDN`, `Reality` |

## 🚦 如何判断节点是否健康可用？

1. **延迟测试 (Ping / Latency)**
   - **TCP Ping (握手延迟)**：仅测试本地到节点的 TCP 建立连接时间，不能完全代表能否实际上网。
   - **HTTP Ping / 真连接延迟**：客户端通过节点实际向 Google 或 Cloudflare 发送 HTTP 请求并测量返回时间。只有真连接测试通过，才说明节点能正常使用。
2. **状态提示词**
   - `Timeout` / `0ms` / `全红`：握手失败或连接超时。详见 [节点全部超时排查](/troubleshooting/all-nodes-timeout)。
   - `200 OK` / `50ms`：节点连接健康，通信正常。
