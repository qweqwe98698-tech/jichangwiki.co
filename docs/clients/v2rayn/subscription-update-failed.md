# v2rayN 更新订阅失败排查指南

<AnswerBox question="Windows 下 v2rayN 点击更新订阅总是报错失败或没反应怎么办？">
按顺序切开以下三个关键结：<br>
1. <strong>分清直连与代理路径</strong>：无节点可用时选<code>更新全部订阅(不通过代理)</code>并关掉底层「自动配置系统代理」；旧节点能通但订阅域名被屏蔽时才选<code>(通过代理)</code>；<br>
2. <strong>清理 URL 头尾空格与浏览器试探</strong>：将链接贴入浏览器看是否报 <code>404 / 403</code> 或返回内容本身出错；<br>
3. <strong>排查 User-Agent 与系统代理端口残留</strong>（必要时核对 <a href="/troubleshooting/subscription-update-failed">订阅更新失败状态码速查表</a>）。
</AnswerBox>

---

## 一、最核心的一步：切准更新通道

| 当前网络实际情形 | 点哪一个菜单选项 | 常见误点导致的报错后果 |
| :--- | :--- | :--- |
| **首次安装 / 老节点全部超时无法上网** | **`更新全部订阅(不通过代理)`** | 若误点「通过代理」，v2rayN 会尝试经由失效老节点连去机场拿配置，必然死锁超时 |
| **至少有一条节点可用，但直连机场订阅被挡** | 开启该可用节点 + **`更新全部订阅(通过代理)`** | 若点「不通过代理」，会被本机宽带 DNS 投毒或直接掐断 HTTPS 握手 |

---

## 二、常见具体故障现象与定向修复

### 1. 核对订阅地址与机场面板状态
进入 `订阅分组 ➔ 订阅分组设置` 核对三件事：
- **没有贴错 Clash 链接**：再次确认这是通用/V2Ray 订阅（关于格式区别对照见 [订阅格式对比](/subscription/formats)）。
- **结尾无换行及空格**：光标点到 URL 末端按 Backspace/右方向键确保干净，并确保链接前未缺字母 `h`。
- **浏览器直开测响应**：将相同链接粘进 Chrome 隐身窗口打开，若是直接报错 `404 Not Found` 或要求重置安全密钥，登录机场官网点「重置订阅地址」后重新贴回 v2rayN（细节可查 [订阅链接打不开处理](/subscription/url-not-working)）。

### 2. 检查被机场 WAF 拒绝的 User-Agent
极少数机场会在后端对异常爬虫做 UA 过滤：
- 进入 v2rayN 顶部 `设置 ➔ 参数设置 ➔ Core:基础设置 / v2rayN 设置`，查找默认或自定义 `User-Agent` 项（部分版本允许直接留空或规范设为常见客户端字样后保存重试）。

### 3. 解开遗留的系统代理死锁
即使你选了不通过代理更新，或关闭了 v2rayN 底部代理开关，假如之前装过另一款代理/Clash 且强行关闭进程，Windows 代理寄存器里仍可能残留 `127.0.0.1:7890`。进系统 `设置 ➔ 网络和 Internet ➔ 代理` 把手动代理关闭，或者重启后再开 v2rayN 更新。

## 常见问题解答（FAQ）

### v2rayN 菜单里「通过代理更新」和「不通过代理更新」到底该点哪一个？

如果所有旧节点已彻底死掉（测速全 `-1`）或者你是第一次导入订阅，必须点「不通过代理更新」，防止自己连自己造成超时死锁；只有当你手里还有能通的备用或老节点、但机场官网/订阅域直连已被阻断时，才选「通过代理更新」。

### 更新订阅时提示「基础连接已经关闭 / 远程主机强迫关闭连接」怎么办？

通常由本地运营商拦截、旧节点残留占着代理环境、或服务端防火墙拦截引起。建议在清空系统代理后切换手机热点直连测试，或在浏览器单独打开该 URL 验证后端健康状态。

### 提示更新成功，但界面底栏节点数一点没变甚至清空了是什么原因？

核查填入的链接是否误贴为 Clash YAML；同时检查订阅分组设置里的「筛选」关键字框，以及机场账号有效期（参看 [导入后无节点排查](/subscription/no-nodes)）。
