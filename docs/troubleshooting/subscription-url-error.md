# 订阅链接无法访问或报 `404 / 500` 排查手册

<AnswerBox question="把订阅 URL 放进浏览器检查时提示 404 Not Found、502 报错或连接被拒怎么办？">
在浏览器直接访问订阅 URL 是判别<strong>「服务端接口问题」还是「本地客户端软件故障」</strong>最快的方法：<br>
• 返回 <code>404 / 401 / 403</code> ➔ <strong>旧 Token 已重置或过期</strong>，登录机场面板重复制最新订阅地址；<br>
• 返回 <code>500 / 502 / 504</code> ➔ <strong>服务商订阅后端维护/过载</strong>，等待 10~30 分钟再试；<br>
• 提示连接超时打不开 ➔ <strong>域名在本地 ISP 被屏蔽或 DNS 污染</strong>，切 4G/5G 热点或查 <a href="/subscription/url-not-working">订阅链接打不开全解</a>。
</AnswerBox>

## 一、如何看懂浏览器返回的 4 种结果

| 浏览器测试现象 | 真实问题归因 | 正确处理方式 |
| :--- | :--- | :--- |
| **直接下载了 `.yaml` / 满屏字母文本** | **订阅链接本身完全健康** | 问题在客户端侧（代理死锁/格式选错），去查 [客户端更新订阅失败排查](/troubleshooting/subscription-update-failed) |
| **页面显示 `404 Not Found`** | 路径改变或你在后台重置过安全令牌 | 立刻回机场官网后台复制最新链接覆盖客户端（操作见 [导入教程](/subscription/how-to-import)） |
| **页面显示 `401 / 403 Forbidden`** | 账户过期违规、设备超限、或 URL 被复制截断 | 登录后台看订单是否失效（参考 [订阅过期自查](/subscription/expired)），重复制完整链接 |
| **显示 `500 / 502 / 504 Bad Gateway`** | 服务商数据库崩溃、面板正做维护迁移 | 耐心等待半小时重试；持续数天无法恢复建议换用 [应急备用线路](/navigation/backup) |

## 二、怎么判断你的链接不是自己贴错了？

在认为服务商服务器出错前，先在地址栏瞄一眼链接首尾：
1. 确保协议头是完整的 `https://`，而不是少了一个 `h` 的 `ttps://`；
2. 检查链接里面是不是混进了中文文字（某些面板一键复制按钮如果文案没做好，会连着「订阅地址：」几个字一并塞进剪贴板）；
3. 核对你的机场 URL 与 [典型订阅 URL 结构](/subscription/subscription-url) 一致：应带有 `/subscribe` 与 `token=` 等特征参数，千万不要把主页登录网址 `/#/dashboard` 拿去做校验。

## 常见问题解答（FAQ）

### 浏览器打开订阅地址明确显示 404 Not Found 怎么办？

`404` 表示该网址路径下的订阅 Token 在服务商数据库已失效或已被销毁（最常见原因是在网页点过一次「重置订阅安全码」或机场升级了面板 API 接口）。登录机场后台重复制新订阅覆盖旧地址即可。

### 浏览器访问显示 502 / 504 Bad Gateway 是我电脑坏了吗？

不是。这证明你的网络和电脑已顺利敲开了机场服务器的大门，只是对方后端生成订阅的程序暂时死机或过载，等待服务商重启修复即可。

### 如果订阅网址在浏览器打不开、连官方主页也一并失联了怎么办？

切换手机流量并在浏览器试开官方公布的防失联页；或排查更新订阅时的“直连 vs 代理”逻辑，详见 [订阅链接打不开综合应对](/subscription/url-not-working)。
