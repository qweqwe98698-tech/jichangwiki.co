# 订阅转换的原理与安全风险防范

<AnswerBox question="什么是订阅转换？使用第三方免费在线转换网站有什么安全隐患？">
<strong>订阅转换（Subscription Conversion）</strong>是通过中间后端程序，将机场原始 Base64 或一种规则格式实时改写成 Clash YAML、Surge 或 sing-box 配置的过程。<br>
<strong>核心风险</strong>：当你把带 <code>token=</code> 的原始订阅链接粘贴到陌生公共网页转换时，对方服务器能<strong>直接看到并留存你的个人订阅凭证</strong>，存在流量被盗用甚至被注入恶意分流规则的风险。
</AnswerBox>

---

## 一、订阅转换在后台是如何运作的？

正常来说，转换器接收一条类似下面结构的请求：

```text
https://转换后端/sub?target=clash&url=你的原始订阅URL(含Token)&config=外部规则模板.ini
```

转换引擎会顺次执行三件事：① **代你向机场拉取原始节点**（此时它已经拿到你的完整机场账号节点凭证）；② **下载模板里的大量 ACL4SSR / 自定义分流规则**；③ **把节点填入模板并重新打包成目标 YAML** 回传给你的客户端。

这意味着只要你用了公网第三方转换节点，每次点「更新订阅」，本质上都是在请别人替你代领一次所有服务器账号。

---

## 二、公共转换站的三大真实隐患

1. **Token 留存与流量盗刷**：恶意站点会定期收割记录到的有效 Token，将节点聚合进免费公开池或转售，导致你的套餐余量异常暴降、在线设备超限被机场封禁。
2. **植入恶意路由与 DNS 投毒**：一旦对方在返回的配置 YAML 里悄悄把特定支付、网银或开发站点指向受控 DNS 与恶意节点，普通用户很难在数千行规则里察觉。
3. **公共后端随时挂掉或限流**：即使站点本身无恶意，高并发公共后端也极易被上游屏蔽或返回 `502 / Bad Gateway`，造成客户端反复更新失败。

---

## 三、更安全的三级替代方案

### 1. 优先方案：直接使用机场原生分格式链接（零转换）
当前主流现代机场面板均支持根据客户端直接下发对应配置文件：
- Clash Verge Rev / Mihomo 生态 ➔ 复制后台 `Clash` 专属入口（见 [Clash Verge 订阅导入](/clients/clash-verge/import-subscription)）
- v2rayN / Shadowrocket ➔ 复制通用或对应软件专用订阅链接

### 2. 改规则不改格式：用客户端原生覆写（Merge / Script）
很多用户找转换站并不是为了换格式，而是想多加两条 OpenAI 或公司内网直连规则。这种需求完全不需要第三方转换——在 Clash Verge Rev 里新建一个「全局扩展覆写 (Merge)」即可在本地离线拼接规则，原始订阅地址不用发给任何人。

### 3. 确需跨格式转换：本地部署 Subconverter（127.0.0.1）
如果手里确实只有纯 Base64 / 单节点列表需要喂给 Clash：
- 在 Windows / macOS 下载开源 **Subconverter** 本地可执行程序，或使用 Docker 在本机运行。
- 将客户端更新目标指向 `http://127.0.0.1:25500/sub?target=clash&url=...`。
- 节点解析与转换全程仅经过本机内存回环网络，**原始 Token 与节点列表不会流向任何第三方转换站点**。

## 常见问题解答（FAQ）

### 机场已经提供 Clash / 小火箭专用链接，还需要再做一次订阅转换吗？

完全不需要。正规机场后端已原生适配主流格式，直接导入官方原始链接最安全；只有在极少数只提供单一格式且你使用的客户端不兼容时，才需要转换。

### 使用网上搜到的免费公共订阅转换网站到底危险在哪里？

你提交的订阅 URL 含有个人鉴权 Token，转换站后台日志可直接记录并拉取你的节点，轻则盗刷你的套餐流量，重则在转换出的配置文件中插入恶意 DNS 或代理路由规则拦截明文请求。

### 如果确实需要定制分流规则或转换格式，最安全的做法是什么？

优先直接在 Clash Verge 等客户端内使用本地 Merge / Script 扩展覆写规则；若涉及不同协议格式互相转换（如 Base64 转 Clash YAML），建议在本机电脑运行开源 Subconverter 或通过 Docker 在本地 `127.0.0.1` 完成转换。
