# 如何更新订阅与设置自动同步策略

<AnswerBox question="为什么要定期更新订阅？推荐设置多久自动更新一次？">
因为机场服务商会定期替换被波动或限流的入口 IP、维护故障机器并新增节点地区。<strong>若长期不更新，本地保存的还是已下线的旧服务器 IP，最终就会大面积超时。</strong><br>
通用最佳实践：开启「软件启动时更新」或设置 <strong>720~1440 分钟（每 12~24 小时）自动静默更新一次</strong>。
</AnswerBox>

## 一、各主流客户端推荐更新策略设置

| 客户端名称 | 自动更新推荐入口与设定 | 建议注意的开关选项 |
| :--- | :--- | :--- |
| **Clash Verge Rev** | 右键订阅卡片 ➔ `编辑信息 (Edit)` ➔ 更新间隔设 `720` 或 `1440` 分钟 | 按需勾选「通过代理更新」（详解见 [Clash Verge 更新订阅指南](/clients/clash-verge/update-subscription)） |
| **v2rayN** | 右键对应分组或分组设置 ➔ 填入自动更新间隔（分钟） | 下拉菜单提供「更新订阅(不通过代理)」与「通过代理」两种快捷触发 |
| **Shadowrocket（小火箭）** | 软件底部 `设置` ➔ `订阅` ➔ 打开 **「打开时更新」** 与后台更新 | 若直连拉取超时，可打开「通过代理更新」或先切节点后刷新 |
| **Clash / Mihomo 核心** | 读取 `profile-update-interval` 响应头，本地覆写为准 | 规则修改应放在独立 Merge/Script 中，避免被远端覆写冲掉 |

## 二、决定更新成败的关键选项：直连 vs 代理更新

很多人在更新订阅这一步卡住，往往不是链接坏了，而是**请求路径自相矛盾**：

- **场景 A：旧节点全挂（大面积 Timeout），此时还勾选了「通过代理更新」**  
  客户端试图把向机场官网请求新节点的 HTTP 请求交给“已经连不上的旧节点”，造成永远打不开的**死锁循环**。  
  ➔ **做法**：先关闭「系统代理」，或点击明确标注了**「不通过代理更新」**的选项直连拉取。

- **场景 B：老节点还能勉强用，但直连机场官网域名已被国内运营商阻断**  
  此时直连请求会被拦截超时，反而必须借助一条尚未失联的可用节点把更新流量送出去。  
  ➔ **做法**：保持代理开启，勾选 **「通过代理更新」** 拉取新配置文件。

## 三、维护订阅长期可用的 3 条好习惯

1. **不要将刷新频率设得过高**：设置每 12~24 小时同步 1 次足够；人为每分钟疯狂刷新可能触发服务商防火墙风控 `429`。
2. **订阅失效先自查余量与到期时间**：超过月度套餐流量或欠费过期也会导致更新不出节点，确认途径见 [订阅过期与流量耗尽判断](/subscription/expired)。
3. **养成留存至少 1 条低成本备用按量线路的习惯**：万一主力机场订阅域与官网同时发生不可抗力故障，立刻切换备用线路才能最稳妥地拉回更新；可按需参考 [备用应急按量机场整理](/navigation/backup)。

## 常见问题解答（FAQ）

### 机场节点用得好好的，平时还需要主动点更新订阅吗？

节点正常时不需要天天手动连点，保持客户端每日自动同步（约 12~24 小时一次）即可；只有当你看到大批节点同时 Timeout 或机场公告新增/调整地区线路时，才需要手动立即刷新。

### 更新订阅时，应该开启「通过代理更新」还是「直连更新」？

如果机场当前有节点依然连通，且订阅官网域名在国内被阻断，应勾选「通过代理更新」；相反，若所有节点已集体失联导致死锁，必须先关闭代理并用直连更新，或换用未封锁订阅域尝试。

### 为什么 Clash Verge 的自动更新间隔重启后又变了？

确保编辑完 Profile 的更新间隔后点击了保存；同时注意部分机场会在下发响应头包含默认周期建议，如果被客户端误重置为新配置覆盖，请避免反复删除重建同一个 Profile。
