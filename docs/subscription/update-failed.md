# 更新订阅失败：核心机理与链路层排查

<AnswerBox question="为什么客户端点击「更新订阅」总是超时或提示 Fetch Failed？">
根本原因通常发生在 <strong>本地网络路由死锁</strong> 与 <strong>客户端请求环境异常</strong>：当所有旧节点已失效、系统代理却依然开着时，客户端发起的更新请求会被强行送进失效代理管道从而必败；反之若订阅域名已在本地被运营商拦截，完全关闭代理直连也会失败。<br>
查看按报错码分类的 30 秒快速修法与各大软件按钮对照，请前往：<a href="/troubleshooting/subscription-update-failed">更新订阅失败状态码与急救手册</a>。
</AnswerBox>

## 一、读懂更新请求的两种典型死锁状态

很多新手发现“昨天还能更新，今天死活转圈”，本质上是网络路径撞进了以下两种逻辑死胡同之一：

| 当前网络前提 | 错误的更新方式 | 结果与症状 | 正确脱困操作 |
| :--- | :--- | :--- | :--- |
| **老节点全挂**（测速全 Timeout） | 开启系统代理 / 选择「通过代理更新」 | 请求发往失效代理端口，无限超时或报连接重置 | **关闭系统代理 ➔ 点击直连（不通过代理）更新** |
| **有节点可用，但订阅域被墙** | 关闭系统代理 / 选择「直连更新」 | 直连运营商拦截 DNS/SNI，报 TLS/连接超时 | **保持一条可用节点开启 ➔ 选择「通过代理更新」** |

> [!TIP] 两头都连不上时的破局点
> 如果家宽 Wi-Fi 直连被屏蔽、老节点又已经彻底过期失效：先切到**手机 4G/5G 热点**让电脑连上热点直连更新；或者开启一条事先保留的[按量计费备用节点](/navigation/backup)挂代理更新主力订阅。

## 二、除网络之外的 4 类隐藏阻塞点

### 1. 系统代理端口残留（Windows 常见坑）
上一款代理软件异常崩溃或被强杀后，Windows 的 IE/系统代理注册表里可能还留着 `127.0.0.1:7890` 或其他失效端口。此时哪怕 Clash Verge 看似处于关闭状态，发起请求依然会去撞那堵“不存在的墙”。
- **处理**：进 Windows「设置 ➔ 网络和 Internet ➔ 代理」，确认“手动设置代理”已关闭；或在 Clash Verge 内把“系统代理”切换开启再正常关闭一次以清理系统变量。

### 2. 开启了 TUN 模式或双软件端口打架
同时开着某款游戏加速器、企业 VPN、浏览器 SwitchyOmega 插件以及代理客户端时，路由接管会相互抢占，导致更新请求迷路。更新订阅前建议暂时退出多余的网络分流工具。

### 3. 本地时间偏差触发 SSL 握手拒绝
机场订阅全部运行在 HTTPS 上。若主机 CMOS 电池老化或虚拟机休眠导致系统时间慢于当前真实日期，所有 TLS 证书校检都会报错。同步互联网时间后即可立刻恢复。

### 4. 客户端 User-Agent 或订阅链接格式过期
少数机场开启了严格 WAF 或只响应特定客户端 User-Agent；另外，如果你的账户曾执行过「重置安全令牌」，老 URL 也会持续报 403/404。

## 常见问题解答（FAQ）

### 节点还能用但一点击更新订阅就失败，最常见的原因是什么？

如果旧节点仍连通却更新失败，常见原因是更新请求走了「直连」而机场订阅域恰好在本地宽带被拦截，此时需要在客户端为该 Profile 开启「通过代理更新」；也可能是客户端正在发送过旧或不被后台允许的 User-Agent。

### 我已经关闭了 Clash Verge 的系统代理，为什么更新订阅还是报错？

检查是否曾经开启过 TUN 虚拟网卡模式且未关闭、系统内同时运行着第二款代理工具或加速软件、或 Windows/macOS 系统代理环境变量仍残留了旧的 `127.0.0.1` 端口监听配置。

### 更新订阅失败和「节点全部 Timeout」是一回事吗？

不是。更新失败指的是客户端与机场官网下发接口通信中断（无法下载最新配置文件）；全部节点 Timeout 则是配置已经拉到，但具体每一条代理服务器线路都连接超时，需要按 [全节点超时排查手册](/troubleshooting/all-nodes-timeout) 处理。
