# 什么是代理订阅（Subscription）与节点聚合？

<AnswerBox question="什么是代理订阅？它在代理工具中起到什么作用？">
<strong>代理订阅（Subscription）</strong>是由代理服务商（机场）动态生成并托管的一条专用 <strong>HTTPS API 链接</strong>，它将服务商分布在不同地区的服务器节点参数、传输协议、分流规则以及套餐剩余用量聚合在一起。<br>
客户端只需要保存这一条订阅地址并定期同步，即可自动完成所有节点的增删、IP 变更与端口更新，无需手工逐条配置服务器。
</AnswerBox>

## 一、订阅机制是如何演进到今天形态的？

理解订阅机制的演化，有助于搞清楚为什么不同老旧软件和新客户端对同一链接兼容程度不同：

1. **单节点手动录入阶段（早期）**：用户逐条填写服务器域名、端口、密码与加密方式。只要中转入口换了 IP，所有用户都得手动改配置。
2. **静态 Base64 批量导入阶段**：服务端把几十条节点编码成一串静态 Base64 文本（如 `vless://`、`vmess://`、`ss://`），虽然免去了逐一输入，但节点维护后依然无法自动刷新。
3. **动态 URL 订阅与策略托管阶段（现代主流）**：机场根据用户请求 URL 上的参数（如 `flag=clash`、`flag=shadowrocket`）实时渲染出带分流规则、测速策略和用量 Header 的完整订阅文件，客户端开机或定时发起 GET 请求即可无感完成同步。

## 二、一条订阅链接背后的数据流向

当你在客户端点击「更新订阅」时，后台实际发生了以下 4 步交互：

```
客户端 (Clash Verge / Shadowrocket / v2rayN)
   │  1. 发起 HTTPS GET 请求（附带专属 Token 与客户端格式标记）
   ▼
机场订阅下发 API (如 Panel / 独立分流下发域)
   │  2. 校验用户套餐未到期且剩余流量 > 0
   │  3. 组装当前在线节点 + 响应头流量统计 (subscription-userinfo)
   ▼
客户端本地配置缓存
   │  4. 校验 YAML / JSON / Base64 语法后覆盖旧节点清单并重载内核
```

正因如此，所有与「订阅」相关的问题往往都能从这 4 个环节找到源头：比如 Token 失效导致 404（第 2 步拦截）、订阅域在本地被阻断（第 1 步超时）、或者格式不匹配导致解析出错（第 4 步失败）。

## 三、新手最容易混淆的 3 个误区

- **误区 1：把机场购买官网当成订阅链接粘贴**。登录页（如 `/#/dashboard`）返回 HTML，只有后台「一键导入」或「复制订阅地址」里的长 URL 才是真正的订阅接口。
- **误区 2：以为订阅导入之后节点永远不会变**。服务商可能每隔几天或数周切换中转入口 IP、新增/下线地区节点。长时间不更新订阅，就可能出现大面积节点 `Timeout`。
- **误区 3：觉得所有软件用同一条链接就行**。不同客户端需要对应格式（Clash 用 YAML，v2rayN/Shadowrocket 常用 Base64，sing-box 用 JSON），盲目混用会直接触发格式解析失败。

## 常见问题解答（FAQ）

### 可以直接把机场官网注册登录网址当成订阅链接导入客户端吗？

不可以。网站首页返回的是人类阅读的 HTML 网页代码，而非节点参数；客户端解析的「订阅链接」必须是在用户后台点击「复制订阅」获取到的专属 API 地址（通常带有 `token` 参数）。

### 更新一次订阅会重置我本机的客户端设置吗？

不会重置客户端本身的系统代理开关、开机自启、端口或外观等全局软件设置；但会用机场最新下发的服务器清单替换旧节点（并覆盖远端自带的分流策略组）。

### 订阅链接泄露给别人会有什么后果？

绝大多数机场的订阅链接内置个人唯一鉴权 Token，无需登录官网后台密码即可直接拉取并消耗你的套餐流量。若不慎在群聊公开，务必立即去后台执行「重置订阅链接」。
